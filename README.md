# Fika Cafe — فقط HTML / CSS / JS + Node.js (بدون npm install)

هیچ کتابخانه‌ای لازم نیست. فقط **Node.js 18 یا بالاتر** (nodejs.org).

## اجرا
```bash
node server.js
```
بعد `http://localhost:3000` را باز کنید. پنل مدیریت: `http://localhost:3000/admin.html`

### ساخت حساب ادمین (ساده)
1. `node server.js` را اجرا کنید و `http://localhost:3000/admin.html` را باز کنید.
2. بار اول، به‌جای صفحهٔ ورود، فرم «ساخت حساب مالک» نمایش داده می‌شود؛ نام، ایمیل و رمز (حداقل ۸ کاراکتر) را وارد کنید. همان لحظه وارد پنل می‌شوید. دیگر لازم نیست چیزی در ترمینال کپی کنید.
3. اگر صفحه را از کامپیوتر دیگری باز کنید، «کد راه‌اندازی» لازم است که هنگام اجرای سرور در ترمینال چاپ می‌شود (برای جلوگیری از اینکه غریبه‌ها حساب مالک را بسازند).
4. بعداً در پنل: آیکن آدم (بالا) ← «حساب من» ← تغییر نام، ایمیل و رمز (با وارد کردن رمز فعلی). با تغییر رمز، نشست‌های دیگر خارج می‌شوند.
5. رمز را فراموش کردید؟ سرور را با این متغیرها اجرا کنید؛ حساب با این ایمیل/رمز ساخته یا بازنشانی می‌شود:
```bash
# Windows CMD
set OWNER_EMAIL=you@example.com
set OWNER_PASSWORD=یک-رمز-قوی
node server.js
```

## متغیرها (اختیاری)
`PORT` (پیش‌فرض 3000) · `DB_FILE` (پیش‌فرض `data/db.json`) · `COOKIE_SECURE` (پیش‌فرض: کوکی فقط روی اتصال HTTPS «Secure» می‌شود تا روی http/گوشی در شبکهٔ داخلی هم کار کند؛ **هنگام انتشار روی `1` بگذار**)

## تست
```bash
node --test
```

## ساختار
```
server.js        سرور، API، احراز هویت، سفارش، موجودی، امتیاز، پنل ادمین (API)
seed.json        داده‌های اولیه (منو، چالش‌ها، ترکیب‌ها)؛ فقط بار اول خوانده می‌شود
data/db.json     دیتابیس (خودکار ساخته می‌شود؛ از این فایل بکاپ بگیرید)
public/          index.html, style.css, app.js (سایت) · admin.html, admin.js, admin.css (پنل)
test/            تست‌های یکپارچه (node:test)
```


## پنل مدیریت (`/admin.html`)
- ورود با حساب Owner / Admin / Staff؛ دسترسی هر نقش در سرور بررسی می‌شود (Staff فقط داشبورد، سفارش‌ها و دیدن موجودی).
- **دوزبانه** (English / فارسی با RTL کامل) و **تم Light / Dark / System**؛ انتخاب‌ها با سایت مشتریان مشترک است و ذخیره می‌شود.
- صفحه‌ها: داشبورد (KPI، نمودار درآمد روزانه با جدول جایگزین، پرفروش‌ها، موجودی کم)، سفارش‌ها (فیلتر وضعیت، جستجو، تغییر وضعیت، لغو با تأیید)، موجودی (افزودن/کم کردن با دلیل، ناموجود کردن، حد هشدار، تاریخچه)، منو و قیمت‌ها، چالش‌ها (ساخت چالش جدید)، گزارش تغییرات.
- روی موبایل سایدبار به نوار پایین و جدول‌ها به کارت تبدیل می‌شوند.

## منوی مشتریان
حالت نمایش Grid / List / Compact / Large، نوار دسته‌ها که هنگام اسکرول بالای صفحه می‌ماند، فونت کوچک‌تر در موبایل، دکمهٔ افزودن که بعد از انتخاب به `− تعداد +` تبدیل می‌شود (در تعداد ۱ آیکن حذف)، و در صفحهٔ سفارش کم کردن یک عدد یا حذف کل آیتم.

## امنیت و دقت داده
- قیمت، موجودی، تخفیف، امتیاز و پیشرفت چالش فقط در سرور محاسبه می‌شود؛ مرورگر فقط نام آیتم و تعداد می‌فرستد.
- رمز با scrypt (salt جدا) هش می‌شود؛ نشست با کوکی HttpOnly + SameSite؛ قفل بعد از ۵ ورود ناموفق؛ Rate limit.
- API ادمین بر اساس نقش (STAFF / OWNER / ADMIN) در سرور بررسی می‌شود؛ تغییرات ادمین در Audit log ثبت می‌شود.
- تغییر موجودی و سفارش‌ها برای همهٔ دستگاه‌ها زنده (SSE) پخش می‌شود.

## استقرار روی سرور
۱) Node 18+ روی سرور، ۲) `node server.js` (با pm2 یا systemd)، ۳) پشت Caddy/nginx با HTTPS و `COOKIE_SECURE=1`، ۴) بکاپ دوره‌ای از `data/db.json`.

## محدودیت‌ها (صادقانه)
- دیتابیس یک فایل JSON است: برای یک کافه و چند ده کاربر همزمان مناسب است، ولی نه برای ده‌ها هزار سفارش یا چند سرور موازی.
- هنوز نیست: تأیید ایمیل / بازیابی رمز، آپلود تصویر محصول، ساخت محصول و دسته جدید از پنل (فقط قیمت، فعال/غیرفعال، ویژه)، ویرایش تنظیمات کافه از پنل.

## بازی‌ها، چالش اولین قهوه و خوش‌آمدگویی
- صفحهٔ اصلی با نام کوچک کاربر سلام می‌کند و هر بار جملهٔ متفاوتی انتخاب می‌شود (بسته به ساعت روز). برای مهمان، سلام ساده و یک متن کوچک برای ثبت‌نام نمایش داده می‌شود.
- چالش «اولین قهوه» فقط برای کسانی دیده می‌شود که هنوز قهوه سفارش نداده‌اند؛ بعد از اولین سفارش قهوه ۳۰ امتیاز می‌گیرند و چالش برایشان ناپدید می‌شود.
- بازی‌ها (`#/games`): «جفت‌یابی دانه» و «کوییز باریستا». سؤال‌ها، چیدمان کارت‌ها و نمره همه سمت سرور بررسی می‌شود. هر بازی تا ۱۰ امتیاز می‌دهد، روزی ۳ بار امتیازدار است و در جدول هفتگی (شروع هفته: شنبه) ثبت می‌شود. به ۳ نفر اول هر هفته ۵۰ / ۳۰ / ۲۰ امتیاز جایزه داده می‌شود (هفتهٔ بعد به‌صورت خودکار). مقدارها در `db.settings.game` قابل تغییرند (`ptsMax`, `daily`, `prizes`).
- محدودیت: بازی حافظه را یک اسکریپت هم می‌تواند حل کند (چون چیدمان به مرورگر داده می‌شود)؛ سقف روزانهٔ امتیاز و حداقل زمان بازی این را محدود می‌کند، ولی جلوی تقلب حرفه‌ای را کاملاً نمی‌گیرد.

## تغییر منو
- منوی اصلی در `seed.json` است (۱۰ دسته، ۶۵ آیتم) و سایت آن را از `/api/bootstrap` می‌گیرد. قیمت‌ها به تومان کامل ذخیره می‌شوند (مثلاً «۶۹» در لیست = `69000`).
- دیتابیس‌های قبلی خودکار مهاجرت می‌کنند: در اولین اجرای این نسخه، منوی قدیمی با منوی جدید جایگزین می‌شود (کاربران، سفارش‌ها و امتیازها حفظ می‌شوند). برای منوی جدید دیگر، `seed.json` را عوض کنید و عدد `menuVersion` را بالا ببرید.
- توضیحات و مواد تشکیل‌دهندهٔ آیتم‌ها فعلاً خالی است و موجودی هر آیتم ۵۰ است؛ از پنل ادمین (موجودی/منو) تنظیم کنید.
- آیتم جایزهٔ «قهوهٔ رایگان» با `settings.freeItem` (فعلاً `latte:0`) تعیین می‌شود.

## توضیحات آیتم‌ها و تصویرسازی (نسخهٔ جدید)

- هر ۶۵ آیتم منو توضیح فارسی و انگلیسی دارد (`descEn` / `descFa` در `seed.json`). برای آیتم‌هایی که ترکیبشان مشخص نبود (سیفانو، کمپانا، پرو شیک، سان رایز، سور پوشن، آیتم‌های وکن بار) متن عمومی «از باریستا بپرسید» نوشته شده؛ لطفاً با متن واقعی جایگزین کنید.
- به‌جای ایموجی، هر آیتم یک تصویر SVG دارد که با فیلد `art` (مثلاً `tall:milk+coffee:ice,straw`) در `public/icons.js` رسم می‌شود. اگر `art` نداشته باشد، تصویر پیش‌فرض دستهٔ خودش نمایش داده می‌شود. آیکن‌های رابط (جام، دانه، مدال و…) هم از همان فایل می‌آیند.
- در هر بار اجرا، توضیح و `art` خالیِ دیتابیس‌های قبلی از `seed.json` پر می‌شود؛ متنی که ادمین نوشته هرگز بازنویسی نمی‌شود. نام انگلیسی «به لیمو» به Lemon Verbena اصلاح شد (شناسهٔ آیتم تغییر نکرده).

## گزینه‌های آیتم، نام‌ها، ترکیب‌ها (نسخهٔ ۴)

- **گزینه‌ها** در `seed.json` با فیلد `groups` تعریف می‌شوند و هر ترکیب گزینه یک «واریانت» است (قیمت و موجودی جدا). واریانت شمارهٔ ۰ همیشه پیش‌فرض است (لاین ۵۰/۵۰، اتیوپی، شیر بادام، تک‌نفره). قیمت همهٔ واریانت‌ها فعلاً برابر قیمت اصلی است؛ برای مثلاً چای دونفره، در پنل ادمین ← منو قیمت همان واریانت را عوض کنید.
- **آیتم‌های جدید** (تونیک پرسو، وایولت، آمستردام، ردبری، شیراز) قیمت نداشتند، پس با قیمت ۰ و **غیرفعال** اضافه شده‌اند. در پنل ادمین ← منو قیمت را بزنید و سوئیچ «فعال» را روشن کنید.
- **ترکیب‌ها** (`combos` در `seed.json`) برگشتند؛ هر ترکیب ۱۰٪ تخفیف دارد و `popular:true` برچسب «پرطرفدار» می‌گیرد.
- در هر بار اجرا، دیتابیس‌های قدیمی خودکار به‌روز می‌شوند (نام‌های جدید، گزینه‌ها، آیتم‌های جدید، ترکیب‌ها) و ویرایش‌های ادمین (قیمت، توضیح) حفظ می‌شود.
- بخش «همیشگی تو / مورد علاقه‌های تو» در صفحهٔ خانه از سابقهٔ سفارش‌های همان کاربر ساخته می‌شود.

## قهوهٔ اسپشیالیتی، قهوهٔ ترک، کتابخانهٔ قهوه (نسخهٔ ۵)

- **قهوهٔ ترک** حالا به‌جای لاین عربیکا/روبوستا، «نوع قهوه» دارد: کلاسیک (پیش‌فرض)، با هل، رست تیره. (در `seed.json`، آیتم `turkish` قابل ویرایش است.)
- **اسپشیالیتی** (اتیوپی و اندونزی برای اوریگامی و هاریو سوییچ): با انتخاب خاستگاه، توضیح خلاصه‌اش زیر گزینه‌ها دیده می‌شود. متن را ادمین می‌تواند عوض کند.
- **پیش‌فرض شخصی:** اگر کاربر مدام یک خاستگاه را سفارش داده باشد (حداقل ۲ بار و دست‌کم ۶۰٪ سفارش‌های اسپشیالیتی‌اش)، همان در همهٔ آیتم‌های اسپشیالیتی پیش‌فرضش می‌شود و برچسب «همیشگی تو» می‌گیرد. در بخش «همیشگی / مورد علاقه‌ها» نوع قهوه (مثلاً اندونزی) روی کارت جدا نشان داده می‌شود.
- **موجودی اسپشیالیتی:** موجودی بر حسب «فنجان» و مشترک بین همهٔ آیتم‌هایی است که از آن خاستگاه دم می‌شوند (اوریگامی و هاریو یک موجودی دارند). در پنل ادمین ← موجودی، ردیف‌های «اتیوپی/اندونزی · قهوهٔ اسپشیالیتی» برای افزودن، کم‌کردن و علامت ناموجود هست و زیر لیست، متن توضیحشان قابل ویرایش است. مقدار اولیه ۶۰ فنجان است؛ آن را با موجودی واقعی عوض کنید.
- **کتابخانهٔ قهوه:** آدرس `#/learn`، با ۸ مطلب کوتاه (محتوا در `public/learn.js`) و یک بخش در صفحهٔ خانه.


## امنیت (نسخهٔ ممیزی ۱۴۰۵/۰۷/۲۳)
مستندات در `docs/security/` (گزارش، یافته‌ها، سطح حمله، مخزن داده، برنامهٔ حادثه). تست‌ها: `npm test` (شامل `test/security.test.js`).

**متغیرهای محیطی جدید**
| متغیر | کار |
|---|---|
| `TRUST_PROXY=1` | فقط وقتی پشت Caddy/nginx خودت هستی (IP واقعی و https را از هدرهای پروکسی می‌خواند) |
| `PUBLIC_URL=https://دامنه` | ساخت لینک بازیابی رمز با دامنهٔ ثابت (نه از هدر Host) |
| `DATA_KEY` | کلید رمزنگاری 2FA و بکاپ‌ها؛ اگر نباشد فایل `data/db.json.key` ساخته می‌شود (آن را جدا از بکاپ‌ها نگه دار) |
| `ADMIN_STRICT=1` | حالت سخت‌گیر برای انتشار: رمز کارکنان ۱۲+ حرف، بدون رمز آسان، 2FA اجباری. با `COOKIE_SECURE=1` خودکار روشن می‌شود |
| `ADMIN_MFA=on` / `off` | روشن/خاموش کردن اجباری بودن 2FA به‌صورت دستی (پیش‌فرض: فقط در حالت سخت‌گیر اجباری است) |

> روی کامپیوتر خودت (حالت محلی) رمز کارکنان ۸ حرف کافی است، رمز آسان فقط هشدار «مطمئنی؟» می‌دهد و 2FA اختیاری است. قبل از انتشار روی اینترنت `COOKIE_SECURE=1` را بگذار تا حالت سخت‌گیر روشن شود.
| `RESET_OWNER_MFA=1` | یک‌بار، اگر مالک گوشی و کدهای بازیابی را گم کرد (با `OWNER_EMAIL/OWNER_PASSWORD`) |
| `HIBP=0` | خاموش‌کردن بررسی رمزهای لورفته (پیش‌فرض روشن، در صورت قطعی اینترنت نادیده گرفته می‌شود) |
| `RETENTION_ANALYTICS_DAYS` (90) · `RETENTION_AUDIT_DAYS` (365) · `RETENTION_ORDER_DAYS` (395) · `BACKUP_KEEP` (14) | نگهداری داده |

**اولین ورود مالک:** بعد از ورود به `/admin.html` صفحهٔ «حساب من» باز می‌شود تا 2FA را راه بیندازی (برنامهٔ Google Authenticator/Aegis/2FAS، کلید دستی) و ۸ کد بازیابی را نگه داری. رمز مشتری حداقل ۸ نویسه است؛ اگر ساده/رایج باشد فقط هشدار می‌دهد («مطمئنید؟») و با تأیید خودش پذیرفته می‌شود. رمز مالک/کارکنان حداقل ۱۲ و بدون رمز ساده.
**فراموشی رمز مشتری:** مالک در «حساب من ← لینک بازیابی رمز» ایمیل مشتری را می‌زند و لینک یک‌بارمصرف ۳۰ دقیقه‌ای را به او می‌دهد.
**بکاپ:** روزانه رمزشده در `data/backups/` (۱۴ روز). بازیابی: `node tools/restore-backup.js data/backups/db-YYYY-MM-DD.json.enc data/db.json` (سرور بسته). یک کپی بیرون از سرور هم نگه دار.
**لاگ امنیتی:** `data/security.log` (ورود ناموفق، قفل، ۴۰۳/۴۲۹، تغییر رمز…)؛ `lockout` و `ALERT` در کنسول هم چاپ می‌شوند.
**ورود:** ۵ خطا در ۱۵ دقیقه ← قفل ۱۵ دقیقه (بعدی ۳۰ دقیقه، ۱ ساعت … تا ۲۴ ساعت)؛ همیشه پیام یکسان «ایمیل یا رمز اشتباه است». نشست مشتری: ۱۴ روز بی‌فعالیتی/۳۰ روز؛ کارکنان: ۳۰ دقیقه/۱۲ ساعت.
**امتیاز:** فقط وقتی سفارش «تحویل‌شده» شود به حساب می‌آید (لغو بعد از آن، امتیاز را برمی‌گرداند).
**تم:** فقط دو دکمهٔ خورشید/ماه؛ پیش‌فرض بر اساس تم دستگاه است.
**استقرار:** پشت Caddy/nginx با HTTPS و `COOKIE_SECURE=1`، `TRUST_PROXY=1`، `PUBLIC_URL`، پوشهٔ `data/` فقط برای کاربر سرویس، BitLocker/رمزگذاری دیسک.
